# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

Phase 0 prepares the project for [feature parity with AASX Package Explorer](docs/software/feature-parity.md).

### Added

- A Makefile as the single entry point for development tasks.
- Linting and formatting with ruff, and type checking with pyright, both enforced in CI.
- Project documentation in `docs/`: architecture, decision records, guides for testing, style, commits, and branching, and instructions for AI agents.
- `python -m aas_editor` as a way to start the application.
- A round-trip test that saves a corpus of packages and compares their objects and file parts, with an optional local mode for packages outside the repository.
- A test that `domain` and `application` do not import PyQt, and helpers in `tests/factories.py` that build BaSyx objects.
- Packages that point to a file missing in the package now open, and list the missing files. Before, 13 of the 132 bundled AASX templates failed to open. Such a package can be saved as JSON or XML, or as AASX after the paths are removed.
- A dialog before a save that would drop content: stored files that nothing refers to in an AASX, and files, the thumbnail and the properties in a JSON or XML file. Save anyway and Cancel, with Cancel as the default.
- A dialog that refuses a save that cannot work: a File without a stored file, a File under an annotation, and a package opened in recovery mode that would overwrite its source. Nothing is written then.
- The context menu action "Add references to all Submodels to the first AAS", which saving did on its own before.
- Files under the annotations of an annotated relationship are read from an AASX. The SDK skipped them.
- The round-trip test now covers the bundled AASX templates, and compares thumbnail, properties and zip entries. A sample runs by default, and `AAS_CORPUS_TEMPLATES=all` runs every template.
- Undo and redo for every edit, add, delete, and paste, with one history of 10000 steps for each package. Undo and redo act on the package of the current item or tab, and show the step in their text, such as "Undo Delete Pump".
- Undo gives back the position of what was deleted, such as an element in the middle of a collection, or a language entry in a description.
- Deleting, cutting, or pasting several selected rows is one undo step, and so is linking all Submodels to the AAS.
- An Edit mode and a Read mode in the View menu. Edit mode is the default. In Read mode every change, including undo and redo, is refused with a message, the editing actions are disabled, and nothing can be edited in a cell.
- A registry for actions in `aas_editor.ui.actions`, so that features add actions to the context menus and the toolbar without changing the tree views. See the [architecture guide](docs/software/architecture.md#registering-an-action).
- A tab whose object was deleted, in another tab or by undo, now closes, and so does a tab of a closed package.
- Values follow their value type. Typing `12` into an `xs:int` Property gives an `xs:int`, and `abc` is refused with a message such as "'abc' is not a valid xs:int: it must be a whole number such as 12 or -3". This holds in cells, in the dialog for one value, and in the add and edit forms, for Property, Range, Qualifier, and Extension. All 31 XSD types work, including dates, durations, and integers beyond 64 bits. The text is checked as you type.
- The value type is chosen from a list of `xs:` names. Before, the form listed Python classes.
- A Range refuses a minimum above its maximum, in cells and in dialogs.
- Changing the value type converts the value through its text in one undo step, such as `"12"` as `xs:string` to the `xs:int` 12. If the value does not fit, the change is refused and nothing changes. A Property in a list that fixes the value type cannot leave it.
- A Blob editor that shows the content as text when it is UTF-8 text, and as hex otherwise, with loading from a file, saving to a file, and the media type of a loaded file. The bytes stay exactly as they were until you edit them, and a Windows text keeps its line breaks. Content above 1 MiB is not shown, and can still be saved and replaced. Typing a Python literal such as `b'text'` is no longer needed.
- The context menu of a Blob has "Load Blob content from file..." and "Save Blob content to file...". Saving also works in Read mode.
- Language tags of display names, descriptions, and MultiLanguageProperty values are checked for BCP 47. A malformed tag, an empty text, or a language used twice is refused with the reason, such as "use a hyphen, not an underscore, as in en-US". The list of languages offers 13 codes instead of 5.
- Adding to a SubmodelElementList opens a dialog for the type of the list, with the value type of the list fixed and the semantic id of the list filled in. Before, any type could be chosen, and the SDK refused the wrong ones afterwards.
- The form of a new SubmodelElementList offers only element types that can be made, and shows `order_relevant` ticked, as the SDK default is true. Editing what a list fixes when it is made, such as `order_relevant`, is refused with a message that says to make a new list.
- Every attribute of the 14 submodel element types can be reached in the form and in the tab, including `direction`, `state`, `messageTopic`, `messageBroker`, `lastUpdate`, `minInterval`, and `maxInterval` of a BasicEventElement, which the original editor lacks.
- Rename id for shells, submodels and concept descriptions, and Rename idShort for elements, in the context menu of the package tree. Both update every reference that has the old id or goes through the old idShort, in semantic ids, supplemental semantic ids, value ids, `refers_to`, the references of a shell, relationships, data specifications and every other field, and in list positions. A preview lists the references that change. The rename and the updates are one undo step. An id or idShort typed in a cell takes the same path.
- Delete shows what refers to the objects, and offers to remove those references or leave them. A reference that is required, such as the end of a relationship, stays. Deleting a shell, submodel or concept description, or an element with elements below it, asks first, and Shift skips that question. Deleting several objects shows one dialog and is one undo step. Cut asks nothing and leaves the references.
- Deleting an item of a list moves the references to the items behind it up by one, so they keep pointing at the same item.
- Fix References in the context menu repairs references that name an object by its idShort instead of its id, and keys that have the wrong type. It lists what it cannot repair.
- Sync idShort copies the idShort of an element to the concept description of its semantic id, where that has no idShort or short name.
- An invalid idShort, or one that a sibling has, gets a suggestion such as `My_motor` or `Name_1`, which the user can accept.
- A test that reads every class of the SDK and fails when the walk over references misses a reference field.
- A Package files panel (View > Panels > Package files, or "Show package files" in the context menu). It lists every supplementary file with its media type, size, and the File elements and thumbnail that refer to it, and marks the files that nothing refers to, because a save to AASX drops them. Buttons add a file from disk, create a text file, edit a text file, rename, move to a central folder, remove, save to disk, and find dangling references. Every change is one undo step, and in Read mode the buttons that change the package are off.
- The same functions in the context menu of the file rows in the package tree, so Rename and Move can be started where the file is.
- Rename and Move update the File elements, the File elements under annotations, and the default thumbnail that refer to the file, in the same undo step, so nothing is left pointing at the old name. A name that another file has, or that differs only in case, is refused instead of merged or numbered by the SDK.
- Names of files are checked as part names. A name with `..`, a backslash, an empty folder name, or characters that the AASX writer refuses is refused with a reason, when a file is added, created, renamed, or moved. Before, such a name was accepted and the save failed later. A file name from disk is made safe: `report final.pdf` becomes `/aasx/files/report_final.pdf`.
- A File element, and the default thumbnail of a shell, can be linked to a file of the package from the context menu: "Choose package file...", "Add file to package and link...", "Create text file and link...", "Edit linked text file...", "Choose default thumbnail from package files...", and "Add file as default thumbnail...". A file that is added and linked gets the media type of the file. A file that is only chosen leaves the media type of the element as it is.
- Text files are created and edited as UTF-8, so non-ASCII text and Windows line breaks survive. A file that is not UTF-8 is not edited as text.
- A file with an unknown extension gets the media type `application/octet-stream`. The original sets `text/plain`.
- Removing a file asks what to do with the File elements and the thumbnail that refer to it: remove the paths, or leave them. Both are one undo step. The same question comes when a stored file is deleted in the package tree.
- Context menu "Find dangling file references...": lists the File elements and thumbnails whose file is not in the package, and repairs them by choosing a stored file, adding a file, or clearing the path.
- The dialog that refuses a save because a File points to a missing file has a button "Repair file references...". The warning about stored files that nothing refers to has a button "Show package files...", which cancels the save so the files can be linked first.
- Copying objects to another open package, with copy and paste or with "Add existing submodel" from a template, copies the files that they refer to, in the same undo step as the paste. A file with the same name and the same content is reused. A different file with the same name, or one that differs only in case, is never overwritten: the copy gets a numbered name such as `doc_0001.pdf` and the pasted paths follow it. The status bar tells what was copied or renamed.
- Validation rules over the objects of a package, in `aas_editor.domain.validation`: 20 rules for the constraints of metamodel V3.1 that the SDK does not enforce (AASd-002, 005, 006, 007, 020, 109, 116, 118, 119, 129, 130, 133), and for duplicate ids, dangling references, missing and unreferenced files, values that do not fit their type, a Range with min above max, and language tags. `validate_package` in `aas_editor.application.validation` runs them in about 45 ms for the largest bundled template. A one-letter idShort is an error, as the metamodel pattern needs two characters, although the SDK accepts it and six bundled templates use it. There is no window for the rules yet.
- A table in `docs/software/validation.md` of which constraints the SDK enforces, which a rule enforces, and which neither can, with a probe of the SDK for each, and what the rules find in the 132 bundled templates.
- A test that pins why 49 of the 132 bundled templates open only in failsafe mode, counted by cause.
- Move up, Move down, Move to top and Move to end for the elements of a submodel, collection, list, entity and annotated relationship, the variables of an operation, and the qualifiers and extensions of an object, in the context menu and with Shift+Ctrl+Up, Down, Home and End. Move up and down are on the toolbar. A move of several selected rows is one undo step, and the rows stay selected. The actions are disabled when the move would change nothing, such as Move up on the first row, and in Read mode.
- Moving an item of a SubmodelElementList gives the references to the items that changed position their new keys in the same undo step (AASd-128).
- Paste above, Paste below and Paste into, with Ctrl+Alt+V, Ctrl+Shift+V and Ctrl+Shift+Alt+V. A paste inserts copies at the position, so pasting again gives a further duplicate, and several copied rows keep their order. Pasting into the annotations of an annotated relationship works. A paste is one undo step, and a refused object leaves the package as it was.
- A pasted element whose idShort a sibling has gets a number (`Pump_1`), and a pasted shell, submodel or concept description gets a new id. A pasted cut keeps its id. The existing Paste does the same.
- Copy puts the SDK's JSON on the system clipboard, and paste reads JSON from the clipboard through the SDK, so elements can move between instances of the editor. Text that is no valid AAS object is refused with a message. Nothing from the clipboard is evaluated.
- Clear paste buffer in the context menu empties the paste buffer and the system clipboard.
- Pasting elements into another package asks whether the concept descriptions that their semantic ids refer to should be copied. A description that the package has with the same content is reused, and one with the same id and other content asks whether to keep the existing one or to add the copy under a new id, which the pasted elements then use. Adding the descriptions is part of the paste's undo step.
- `application/operations/companions.py` gathers what goes with a copy between packages, as one place for later work to add the supplementary files.
- Convert to another element type, in the context menu of an element (F-EDT-04 Refactor). A Property becomes a Range, a collection becomes a list, an Operation becomes a collection, and so on. The idShort, names, descriptions, semantic ids, qualifiers, and extensions carry over. Before anything changes, a dialog lists what the new type cannot hold, such as the maximum of a Range, the other languages of a text, or the items a list does not accept, and Cancel is the default. A conversion that loses nothing asks nothing. The element keeps its position, the references to it keep pointing at it, and the conversion is one undo step. The original editor drops extensions, the second end of a relationship, and all variables of an Operation without a message. See [ADR 0012](docs/software/adr/0012-replacing-an-element-shows-what-is-lost.md) for what each pair carries over.
- A File converts to a Blob with the content of the stored file, or with its path as text, as the user chooses.
- Change list settings, in the context menu of a SubmodelElementList. It rebuilds the list with another type of items, value type, semantic id, or order flag, which the SDK fixes when the list is made. The items that fit stay, in order, and the ones that do not are named before the list changes. "Detect from the items" fills the settings from what the items share. Editing one of these attributes in a cell now points to this action.
- An item of a SubmodelElementList shows a read-only `index` row with its position, where it showed the name that the SDK generates. The row follows items that are added, removed, or moved.
- Change attribute with a pattern, in the context menu of the package tree. It changes the idShort, description, display name, or text value of the selected objects. A table shows the result for every object before anything changes: changes, unchanged, skipped (such as an object without the chosen language), and refused with the reason. An invalid idShort, one that a sibling has, a text beyond the length the metamodel allows, and a value that does not fit its type are refused, and nothing applies until the pattern or the selection changes. The renames update the references in the same step, elements can swap names, and the change is one undo step. The pattern language is new and documented in [Bulk editing](docs/software/bulk-editing.md), with examples. The original's language is not used, and nothing in a pattern is evaluated.
- Remove extensions, for the selected objects, by name or by semantic id, with the count of each, as one undo step.
- Add a qualifier, extension, specific asset id, or data specification from a preset to all selected objects (F-EDT-07, F-EDT-06). The presets are JSON files in the SDK's serialization: those of the app are in `aas_editor/presets/`, and those of the user are in the `presets` folder next to `settings.ini`, where a preset replaces a shipped one of the same name. The preset files of Package Explorer can be copied there. A file that is missing, damaged, too large, or not JSON never stops the editor, and each refused entry is listed with its reason. A preset of a specific asset id without a value asks for it, because the SDK refuses an empty one. See [ADR 0017](docs/software/adr/0017-presets-and-the-pattern-language.md).
- Add a qualifier, extension, or specific asset id from the clipboard, to all selected objects. The JSON is read by the SDK, and text that is not valid is refused with the reason, such as "This is a Property, not a Qualifier". An object that has the qualifier type (AASd-021), the extension name (AASd-077), or the member already is skipped and named, and the others still get it.
- The preset and clipboard actions also work in a tab, on the row of `asset_information` or of `qualifier`, and on a shell in the package tree for specific asset ids.
- A text of several lines can be typed. An `xs:string` value has a box of several lines in the value dialog and in the add and edit forms, and so does the text of each language of a MultiLanguageProperty, a description, or a display name. The text comes back exactly as it was while nothing is edited, including Windows line breaks. An `xs:normalizedString` stays a line, because the SDK refuses a line break in it.
- Create AAS in the context menu of the package tree asks for the id, the asset kind, the global asset id (generated, with a Generate button), the asset type, and specific asset ids. A new AAS always has valid AssetInformation. The Add of the shells node uses the same dialog.
- Create Submodel asks for the id, the kind, and the AAS that should refer to it. The Submodel and its reference are one undo step. "Link existing Submodels..." in the context menu of an AAS lists the Submodels it does not refer to and links the ticked ones in one step.
- "Generate global asset id" and "Add specific asset id..." in the context menu of an AAS, each one undo step. Removing the last asset id is refused with the reason (AASd-131).
- "Remove attributes..." in the context menu of a Submodel removes all qualifiers, extensions, descriptions, display names, or categories from the Submodel and every element below it, including annotations, entity statements, and operation variables. The dialog names the number of each, and the question states what goes. It is one undo step.
- A reference picker in every form that enters or edits a reference: `semanticId`, supplemental semantic ids, `valueId`, `refersTo`, the value of a ReferenceElement, the ends of a relationship, the Submodels and `derivedFrom` of an AAS, `externalSubjectId`, `isCaseOf`, `observed`, and `messageBroker`. "Choose from package..." lists the shells, Submodels, concept descriptions, and elements of the package, filtered by the target type that the field accepts, with a search. It derives the keys: an external reference to the id of a concept description, or a model reference through the path. An element gets a model reference, because it has no id. The keys stay editable, so an external reference to anything can still be typed.
- Under the keys of a reference, a line says whether it resolves, is dangling (and which key is missing), or points outside of the package. The target type of a model reference follows the type of its last key.
- When the keys break AASd-121 to 128, the form shows the reason in place of a traceback, and OK stays off until the keys are right. A reference without keys says to add one or choose a target.
- "Jump to target" in the context menu of a reference in a tab opens the target in the same tab, so Back returns to the object being edited. A reference that resolves in part opens the closest object and names the key that was not found. A reference to nothing, or to something outside of the package, says so. An external reference whose id belongs to an object of the package also jumps. It works in Read mode.
- Paste into an AAS: a copied Submodel is added with a new id, or its own id after a cut, and the AAS gets a reference to it. A copied reference to a Submodel is added as it is. A reference that the AAS holds already is skipped, with a message. A Submodel from another package comes with its concept descriptions and files. One paste is one undo step.
- `domain/reference_picker.py`, `domain/asset_information.py`, `application/operations/create.py` and `bulk.py` hold the rules without Qt, and `domain/walking.descendants` walks entity statements and operation variables as well.
- Concept description tools in the context menu of the package tree (F-EDT-05, F-EDT-04, F-EDT-03). Every one is a single undo step and is off in Read mode.
  - "Create concept description from semantic id" adds the description that the semantic id of a submodel or element names, with the first key as its id, and the idShort, the description and an IEC 61360 record with the preferred name and definition of the element. "Create concept descriptions from all semantic ids..." does that for everything below, and asks whether the new descriptions get the record. Ids that a description has already, or that another kind of object has, are reported and skipped.
  - "Assign concept description..." sets the semantic id of the selected elements to a description chosen from a filtered list. It is an external reference with the id as a global key. A semantic id that the element has is replaced only after a question that shows the old and the new one.
  - "Auto-detect concept descriptions..." gives each element without a semantic id the description with its idShort (exact match first, then ignoring case). It lists the elements first. Several matches are skipped and reported, a semantic id that is set is never replaced, and an item of a list, which has no idShort, is left alone.
  - "Create concept descriptions from value list..." adds one description for each pair of the value list of a description. The pair's value id is the id, and the value gives the idShort, the display name, and an IEC 61360 record with the data type `STRING_TRANSLATABLE`. A pair without a value id is skipped with the reason, where the original made a description with a null id. The value list stays as it is.
  - "Delete invalid concept descriptions..." lists the descriptions with no data specification, no isCaseOf and no extension, with the number of references to each, and deletes the ones that stay selected through the delete flow, which shows the usages and offers to remove those references.
  - "Add IEC 61360 record..." and "Edit IEC 61360 record..." open a dialog for all attributes: preferred name, short name and definition in any languages, the data type (all 19 literals, grouped), unit, unit id, symbol, value format, value, source of definition, and the four level types. The record gets the template key. The SDK does not allow an empty preferred name, so the dialog starts with the idShort of the description, says what is missing, and keeps the button off until the SDK would accept the record. Lengths (18, 255, 1023, 2048) and language tags are checked while typing, with the reason. Constraints that the SDK does not check, AASc-3a-009 (a measure needs a unit), AASc-3a-010 (a value excludes a value list) and AASc-3a-008 (a definition in English), are shown as notes.
  - "Remove empty IEC 61360 attributes" takes away a unit, symbol, source of definition, value format or value list that is present but empty, which the SDK accepts and the schema does not. The preferred name stays.
  - "Fix data specification keys..." gives every record with IEC 61360 content the key of the template, for all records of each description, where the original fixes only the first. Records that name the template in an older spelling (such as `http://` or `3/0`, which all 35 records of the contact information template use) are changed only when the user ticks a box.
  - "Import value list from clipboard..." reads pairs from lines (`value, valueId`, or separated by a tab, as a spreadsheet copies), from a JSON array of pairs, from one pair, or from a whole value list, shows a preview with the result for each entry, and adds the new pairs. Pairs that the list has are not added twice. An entry that is not usable is skipped with the reason, and text that cannot be read at all is refused with a message. Nothing from the clipboard is evaluated; JSON goes through the SDK's decoder.
  - "Order concept descriptions..." lists them in the view by name, list index (the order of the file), idShort, id, first use in the submodels, by submodel elements, or structured (SAMM aspects with what they reach, then what submodels use, then the rest). It changes the view only.
  - "Sort concept descriptions in the file..." writes the order of the view into the file, after a preview, as one undo step. It sorts by name, idShort, id and first use, and for the list index, by submodel elements and structured it says `The file cannot keep this order, so nothing was sorted` and changes nothing. After a sort the view lists the descriptions by list index.
  - "Create empty concept description" adds a description with a generated id and nothing else, and selects it. It is on the node of the descriptions and on submodels and elements, and leaves the semantic id of an element as it is.
  - A tab of a submodel or an element with a semantic id shows the concept description that it names below the attributes, read-only and collapsed to one line, with a button that opens the description in the tab. A semantic id that names no description shows `The package has no concept description that this semantic id names`.
  - The IEC 61360 dialog lists the pairs of the value list and removes one pair or the whole list. A record without pairs has no value list.
  - A concept description whose extension carries a SAMM element (versions 1.0.0, 2.0.0 and 2.1.0) lists `id` and `administration` before the other attributes, and gets no hint about a missing data specification. The hint "A concept description has a data specification" is new, in hints mode, for the others.
- The reference picker lists the targets of the other open packages too, names the package of each, and can leave them out. A reference to a target of another package is the same as one to a target of this package.
- Rules AASc-3a-004 to 007: a concept description with the category PROPERTY, VALUE, REFERENCE, DOCUMENT or QUALIFIER_TYPE needs an IEC 61360 data type that fits, as Part 3a says. The sets of data types are those of the published text of Part 3a (IDTA-01003-a V3.1.1), and the messages are our own. None of the 132 bundled templates breaks them.

- A Validation dock (View > Panels) lists the findings of the rules for the current package: severity, rule, location, and message. A severity filter and a rule filter hide what the user does not want to see, such as the 569 dangling references of the bundled templates, and a sentence counts the findings and what the filters hide. A double click selects the element of the finding in the package tree, and a finding about the package selects the package. The dock follows the package of the current row, clears when that package is closed, and runs the rules about 250 ms after the last change, so editing and undo never wait for them. A hidden dock runs nothing. See [ADR 0015](docs/software/adr/0015-validation-in-the-editor.md).
- Saving runs the rules (D5). A package that breaks a rule of the specification asks "Save anyway" with the rule, the place, and the message, next to the content that the save drops. The two file errors that the SDK cannot write still refuse the save, once and with the target in mind. Warnings never interrupt. The same errors are asked about once per package and session, so the six bundled templates with one-letter idShorts do not ask on every save. A rule that raises is logged and shown as a warning of the rule `EDT-RULE-FAILED`, and the save goes on.
- Hints mode (View, on at first, as in Package Explorer). A bar above the attributes of a tab lists the rules that the shown object breaks and hints such as a deprecated category, whitespace in a semantic id, an idShort with three dashes, and an empty or shared global asset id. The create dialogs show the same checks under the idShort, key value and global asset id fields while the user types. Hints never block typing, accepting a dialog, or saving.
- Read mode shows no row for an attribute that has no value (F-EDT-01 AC1). Edit mode brings the rows back, and the tabs change with the mode.
- The changed marker follows the saved state in all tabs (F-EDT-01 AC3). A save clears it, and so does an undo that returns to the saved state. The package tree and every tab read the same marks, and the objects above a changed object are marked too.
- `validate(..., tolerant=True)` and `validate_package(source, with_hints=...)`, and `SaveGate` in `application/validation.py`.
- A package that opens only in failsafe mode now tells what the SDK left out. A dialog opens with the package: a summary ("Left out: 3 objects (2 concept descriptions, 1 submodel), 1 element and 5 details"), the full list with the biggest losses first, each with its line or id and the reason of the SDK, and a button that copies the list with the records of the SDK. Before, the editor said only that something might be missing. All 49 bundled templates that need failsafe mode have a list, and the 83 that open strictly have none. See [ADR 0018](docs/software/adr/0018-load-report.md).
- "Show what was left out when opened..." in the context menu of a package brings the list back later, and the dialog that refuses to overwrite the source names what is missing, lists the first ten items, and has a button for the full list. The list is kept in the crash recovery.
- `PackageParts.load_report` and `domain/load_report.py`, with the records of the SDK as structured data: severity, whether the object was left out or kept, the kind, the line or id, the part, the reason, and the text in full. A message that the parser does not know is kept whole and shown as not understood.
- A test that checks the list against the `idShort` entries in the XML of all 132 bundled templates: the entries that the loaded objects lack are exactly those below the places that the list names.
- A Selection panel (View > Panels > Selection) below the package tree. For two rows or more it shows `Several elements selected`, the kinds and the parent of the rows, and buttons for Move up, down, to top and to end, Cut, Copy, Delete, Change attribute, and Remove extensions. Each button is the action of the menu, with the same enabled and disabled states. The panel opens by itself for the first multiple selection, and stays closed after you close it (F-EDT-09 AC1).
- Push location and Pop location (Navigate menu, `Ctrl+Shift+P` and `Ctrl+Shift+O`, as in Package Explorer). Pop selects the row that was pushed, with the expand state it had, skips rows that are gone, and does nothing when nothing was pushed (F-EDT-01 AC10, AC11).
- "Paste from text..." in the context menu: a box for the JSON of copied elements, with the place to paste it (below, above, or into the selected row). It works when the clipboard cannot be read, and does not touch the buffer (F-EDT-08 AC8).
- "Copy AAS with new Submodel ids..." on an AAS, and on the node of the shells, where it asks which AAS. The copy, its global asset id, and each Submodel it refers to get new ids, the copy refers to the copied Submodels, and references between the copies follow. One undo step. It is not offered on the package (F-EDT-02 AC3, AC4).
- "Remove default thumbnail..." on an AAS, with a question. The file stays in the package, and the thumbnail can be chosen again (F-EDT-02 AC14).
- The package thumbnail can be changed: "Change package thumbnail..." on the package, and a button in the Package files panel, which also names the current one. The image is stored as `/thumbnail.<extension>` in the root of the package, as the original does. It is one undo step, is saved, and survives a crash (F-EDT-10 AC5).
- The Package files panel takes several rows, and Remove removes them all in one step with one question about the references.

### Known limits

- An AASX that declares a supplementary file with an `aas-suppl` relationship that no File element and no thumbnail names opens without that file, and a save does not write it. The SDK reads the files that elements name, and the writer keeps only those (ADR 0013). The Technical Data template declares six files and has one that an element names, so a plain save of it leaves five images out. The package files panel does not list them, and the load report does not say so.
- The type, `order_relevant`, semantic id, and value type of a SubmodelElementList cannot be changed after the list is made, because the SDK has no setters. Make a new list.
- A string with line breaks is shown in a value line but cannot be typed there.
- A File under the annotation of an annotated relationship still blocks a save to AASX, because the SDK writer skips such files. Save as JSON or XML, or move the File out of the annotation.
- Files cannot be dropped on the panel. "Centralize file" to an external store is out of scope, because it writes to a remote store at once, outside the undo history. "Move file to folder" does the same inside the package.
- Selecting a stored file in the package tree opens a preview tab with QtWebEngine. A test process that did that ends with an access violation (exit code -1073741819) after its tests passed, and prints no summary, in each of three runs on 2026-11-06. The session `QApplication` of the tests outlives the web engine. The application does not show it: three runs of the real entry point that selected a stored file and quit ended with code 0, and `tests/large/test_application_exit.py` does the same with an open package. That was on an offscreen platform, where the preview is black, so it is not verified on a real display. The large tests switch the preview off where they do not test it.
- 49 of the 132 bundled templates open only in failsafe mode, and the SDK leaves out what it refuses to read: 91 objects, 26 elements and 83 details, which the editor now lists. The content is still lost: it is not in the open package, and not in a copy saved with Save As, because the SDK does not give it to the editor. By a count of `idShort` entries, 45 of the 49 load fewer than their file has, and the three Bill of Materials extension templates load 20 of 40, because one submodel is gone. Their packages have defects that the SDK refuses to read: 30 share an id between objects, and the others break constraints such as AASd-014, 021, 022, 109, 123 or 131. No reader option can keep that content, so Save As stays the only way to save them. See [the causes](docs/software/validation.md#why-49-of-the-132-templates-open-only-in-failsafe-mode) and [ADR 0018](docs/software/adr/0018-load-report.md).
- The SDK's failsafe reader for JSON raises for a reference with no keys and for a value that does not parse, where its XML reader skips the item. Such a JSON file cannot be opened, not even after the question about recovery mode.
- The list of what was left out counts records of the SDK. One failed item can hold a whole tree, and an element that failed inside a submodel that failed as well is counted twice. A second object with an id that another has, in the same XML document, is listed without saying whether it equals the first, which the SDK does not hand over.
- The main toolbar of the tree needs about 790 pixels for all its buttons, with the text buttons "Paste above" and "Paste below". In a window of 1194 pixels, which is the smallest first window, it still cuts them into a "..." menu, and the tree does not get more, because the tab needs its room. A first window on a larger screen shows all of them. This was seen offscreen, and the real display was not tried after the change.
- A row of the tree that is no AAS object, such as a qualifier row, puts its readable text on the clipboard when copied, as it put its repr before. Copy does not put the JSON of a qualifier or extension on the clipboard, so "Add qualifier from clipboard" cannot take it. `dump_members` exists for that and is not called by Copy.
- The validation rules check what the SDK leaves open, and cannot check AASd-012, or AASd-006 and AASd-007 when `valueId` points outside the package.
- Hints cover the cases that the rules and eleven hint rules know. The notices of Package Explorer about missing semantic ids, and the hints for the Qualifier and data specification sections, are not done.
- A row of a language list cannot hold an empty text, because the SDK refuses one (and an empty list). "Create w/ default" and the default languages give rows that wait for text in the dialog, and a row that stays empty is left out. The original keeps an empty entry in the model.
- The asset kind `Batch` is a literal of metamodel V3.2, which the SDK does not have. A file that has it is refused as a whole, and in failsafe mode the shell is left out and the package is partial (F-EDT-02 AC11).
- An attribute row that holds a text or number is not coloured as changed, because a mark names an object and Python shares texts. The object above it is marked.
- The Validation dock lists the package check, not the hints. Fixing a finding (F-PKG-04 Fix) is not done beyond Fix References.
- The rules run in the thread of the UI. A package ten times the size of the largest template would take about half a second after each pause in editing.
- Shells, submodels, concept descriptions and the Submodel references of a shell cannot be moved one at a time (D16). The store of the package keeps the order of the file for the first three, so a sort of the descriptions can write an order, and a move could now be built. The Submodel references of a shell are in a set whose order is not saved. The tree sorts the three kinds by name unless the user chooses another order of the descriptions.
- Cut still removes the element at once (D12), so Escape or a missing paste does not bring it back, except by undo.
- A paste of elements into a SubmodelElementList does not check the type of the list in advance. The SDK refuses a wrong element (AASd-107), the paste is undone as a whole, and the message says why.
- The paste buffer and the system clipboard are one: a newer copy anywhere replaces the buffer. The original keeps its internal buffer first. This is a decision ([ADR 0020](docs/software/adr/0020-selection-locations-and-clipboard.md)).
- Converting a text or a Property to a File can give a path that no stored file has. Saving reports such a File.
- The item of a SubmodelElementList cannot be converted to another type, because the list fixes it. Change the list settings instead.
- A cell of the package tree or of a tab is still one line. Use Edit to type line breaks.
- The reference picker lists the open packages. ECLASS, IEC CDD, and the pool of known concepts are out of scope (F-EDT-11). A stored file is no target of a reference, because V3.1 has no key type for one: the File element has a chooser of its own.
- A reference copied from another program is not pasted into an AAS, because only copies made in the editor keep a reference. Copy the Submodel instead.
- Jump to target is in the tabs only, because the package tree does not show references. A key of a reference is not a jump target of its own.
- The Create AAS dialog does not ask for the external subject id of a specific asset id. Edit it in the tab afterwards, with the picker.
- Remove attributes offers qualifiers, extensions, descriptions, display names, and categories. Semantic ids and data specifications are not offered, because removing them breaks the constraints of lists (AASd-107) and templates.
- A selection cannot be moved into another parent, because that changes the path of each element and of every reference through it. Use Cut and Paste, which keeps no references.
- A preset cannot be saved from the editor. Edit the file in the `presets` folder. Presets of other data specifications than IEC 61360 cannot be made, because the SDK has no content class for them.
- Changing the attributes of a selection works on the selected rows of the package tree. The actions for presets and the clipboard also work on the rows of a tab, but the pattern change and the removal of extensions do not.
- A bulk change of an idShort does not run the validation rules (for example a one-letter idShort is accepted as the SDK accepts it).
- A pair of a value list needs a value id. The SDK writes a pair without one as `"valueId": null` in JSON, which its own reader refuses, and then drops the pair with the whole description in failsafe mode. Pairs without a value id are therefore not imported.
- The order of the pairs of a value list is not saved, because the SDK keeps them in a set.
- The list index, first use, by-element and structured orders of concept descriptions are worked out when they are chosen, and do not follow later edits until chosen again. They order the one list of descriptions. They do not nest the descriptions under the elements that use them, as the tree of Package Explorer does.
- The IEC 61360 record dialog removes the pairs of the value list but does not edit them (use the import), and shows a unit id only as the value of one global reference.
- A concept description cannot have a data specification of another kind, because the SDK has only the IEC 61360 content. An element's idShort is never empty in a submodel (AASd-117), so the original's "take the idShort from the description" has no case. The SDK cannot hold a blank qualifier, extension or data specification record, so no preset has one to replace.
- SAMM descriptions are recognized (identification first, no hint for a missing data specification, the structured order), and not modeled: the elements are edited as the extension that holds them. Concept descriptions from ECLASS are not done.
- The embedded display of a concept description in the tab of an element is read-only. Edit the description in its own tab, which the button of the display opens.
- The keys of the shortcuts are not pressed in a test, because the offscreen platform has no active window and Qt then sends no shortcut. Each gesture is checked to belong to one action of the view.
